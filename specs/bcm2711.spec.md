# Broadcom BCM2711: the stock Arm stub (permissive overlay)

Adds to the `bcm2711` spec in `hardware-specs-docs` the entry-state facts that only the source of
the Raspberry Pi Arm stub states. The board-spec format has no class for a fact read from code,
so each bullet below is an `[inference]` whose premises are anchored to the stub's source at the
pin below (anchor grammar: driver-lab's `peripheral-spec`), plus documents where they help. The
step every bullet shares, and the reason each carries a TODO: the firmware's built-in stub for a
BCM2711 board is the `armstub8-gic` build of `armstub8.S`. The firmware documents only that its
default stub is built in and chosen per model; the Makefile builds `armstub8-gic.bin` with
`-DGIC=1 -DBCM2711=1` and emits it as the `armstub8_gic` array of `armstubs.h`, the form a
firmware build would embed.

Source pin: rpi-tools@439b6198a9b340de5998dd14a26a0d9d38a6bcac BSD-3-Clause

## Quick-facts

- **Generic timer frequency.** At kernel entry `CNTFRQ_EL0` reads 54 MHz (54000000) and
  `CNTVOFF_EL2` is 0. `[inference]` (premises: the BCM2711 build defines `OSC_FREQ` as 54000000
  `[src:rpi-tools: armstubs/armstub8.S:53-57 (OSC_FREQ)]` and writes it to `CNTFRQ_EL0`
  `[src:rpi-tools: armstubs/armstub8.S:110-112 (OSC_FREQ)]`, then zeroes `CNTVOFF_EL2`
  `[src:rpi-tools: armstubs/armstub8.S:114-115 (CNTVOFF_EL2)]`; the BCM2711 build is the `-gic`
  one `[src:rpi-tools: armstubs/Makefile:23-24 (CC8)]`; derivation: the shared step above)
  `TODO (verify on hardware)`: read CNTFRQ_EL0 from the kernel on a board running the stock stub.
- **SCR_EL3 value.** Before leaving EL3 the stub writes `SCR_EL3` = `0x5B1`: RW (bit 10), HCE
  (bit 8), SMD (bit 7), the two RES1 bits 5 and 4, and NS (bit 0). `[inference]` (premises: the
  `SCR_VAL` definition and its bit names `[src:rpi-tools: armstubs/armstub8.S:59-66 (SCR_VAL)]`
  and the write to `SCR_EL3` `[src:rpi-tools: armstubs/armstub8.S:121-123 (SCR_VAL)]`;
  derivation: 0x400 + 0x100 + 0x80 + 0x20 + 0x10 + 0x1 = 0x5B1, and the shared step above)
  `TODO (verify on hardware)`: the value is set at EL3 and cannot be read from EL2; confirm by
  checking that an SMC from EL2 traps as undefined.
- **Entry exception level and state.** The primary core enters the kernel in AArch64 EL2 using
  SP_EL2 with D, A, I and F masked, `SCTLR_EL2` = `0x30C50830` (MMU, data and instruction caches
  off, little-endian), `x0` = the device-tree address, `x1`–`x3` = 0. `[inference]` (premises:
  `SPSR_EL3_VAL` selects EL2h with DAIF set `[src:rpi-tools: armstubs/armstub8.S:74-80
  (SPSR_EL3_VAL)]`; the stub writes `SCTLR_EL2`, whose comment says the set bits are RES1 and
  M, C, I, A, SA and WXN are clear `[src:rpi-tools: armstubs/armstub8.S:136-141 (SCTLR_EL2)]`;
  it returns to EL2 with `eret` `[src:rpi-tools: armstubs/armstub8.S:143-148 (SPSR_EL3_VAL)]`;
  the primary core loads `x0` from `dtb_ptr32`, clears `x1`–`x3` and branches to
  `kernel_entry32` `[src:rpi-tools: armstubs/armstub8.S:163-171 (primary_cpu)]`; the arm64 boot
  protocol asks for this state `[standard]` (Linux arm64 booting.rst, "Call the kernel image");
  derivation: the shared step above) `TODO (verify on hardware)`: read CurrentEL and SCTLR_EL2 at
  kernel entry.
- **Patch words the firmware fills.** The stub image holds a magic word `0x5AFE570B` at offset
  `0xF0`, a version word at `0xF4`, a 32-bit device-tree pointer at `0xF8` and a 32-bit kernel
  entry address at `0xFC`; the last two are zero in the image, so the firmware supplies them,
  and after reading the magic it clears the eight bytes at `0xF0` for reuse as core 3's release
  word. `[inference]` (premises: the four words and their offsets `[src:rpi-tools:
  armstubs/armstub8.S:193-208 (stub_magic)]`; the comment on the shared slot
  `[src:rpi-tools: armstubs/armstub8.S:187-192 (spin_cpu3)]`; the firmware writes the kernel
  and device-tree load addresses into such words when the image carries a magic value `[doc]`
  (Trusted Firmware-A documentation, Raspberry Pi 4 platform, "TF-A port design"); derivation:
  the stub reads both pointers and never writes them, so their values come from the loader; the
  shared step above) `TODO (verify on hardware)`: dump the first 256 bytes of RAM at kernel entry
  and compare.
- **Secondary-core release: spin-table.** Cores 1–3 wait in the stub with `wfe`, each polling a
  64-bit word chosen by `MPIDR_EL1` Aff0 (bits 1:0): `0xD8` (core 0's slot, unused), `0xE0`,
  `0xE8`, `0xF0`. A non-zero value is the address they jump to, with `x0`–`x3` = 0. The words
  are physical addresses, since the stub sits at address 0. `[inference]` (premises: the core
  number from `MPIDR_EL1` `[src:rpi-tools: armstubs/armstub8.S:151-153 (MPIDR_EL1)]`; the
  polling loop `[src:rpi-tools: armstubs/armstub8.S:155-161 (spin_cpu0)]`; the slots
  `[src:rpi-tools: armstubs/armstub8.S:175-189 (spin_cpu0)]`; the stub is loaded at DRAM address
  0 `[doc]` (Trusted Firmware-A documentation, Raspberry Pi 4 platform); the spin-table protocol
  `[standard]` (Linux arm64 booting.rst, spin-table enable method); derivation: the shared step
  above) `TODO (verify on hardware)`: confirm cpu-release-addr in the live device tree matches.
- **GIC state at entry.** The BCM2711 stub programs the GIC-400 at EL3 before dropping to EL2,
  with the distributor at `0xFF84_1000` and the CPU interface at `0xFF84_2000` (Low Peripheral
  mode). Every core writes `0x1E7` to its CPU-interface control register and `0xFF` to its
  priority mask and marks the first 256 interrupts group 1; the write of 3 (both groups on) to
  the distributor control register is made only by cores whose `MPIDR_EL1` bits 1:0 are
  non-zero, as core 0 branches past it under a comment that calls it the primary core.
  `[inference]` (premises: `GIC_DISTB` and `GIC_CPUB` for the default build
  `[src:rpi-tools: armstubs/armstub8.S:45-51 (GIC_DISTB)]`; `setup_gic` is called when `GIC`
  is defined `[src:rpi-tools: armstubs/armstub8.S:133-135 (setup_gic)]`; its body
  `[src:rpi-tools: armstubs/armstub8.S:214-235 (setup_gic)]`; `IT_NR` is 8 registers
  `[src:rpi-tools: armstubs/armstub8.S:85-89 (IT_NR)]`; derivation: 8 group registers of 32 bits
  cover 256 interrupts, and the shared step above) `TODO (verify on hardware)`: read
  GICD_CTLR, GICD_IGROUPR0 and GICC_CTLR from the kernel on cores 0 and 1.

## Gotchas

- **No EL3 runtime with the stock stub.** The stock stub sets `SCR_EL3.SMD` and leaves EL3 for
  good with one `eret`, installing no EL3 exception vectors, so there is no secure monitor to
  call: no SMC-based PSCI, and secondary cores come up only through the spin-table. For PSCI,
  load Trusted Firmware-A's BL31 with `armstub=`. `[inference]` (premises: `SCR_SMD` is set in
  `SCR_VAL` `[src:rpi-tools: armstubs/armstub8.S:59-66 (SCR_VAL)]`; the stub's only EL3 code
  ends in `eret` to EL2 and never sets `VBAR_EL3` `[src:rpi-tools: armstubs/armstub8.S:91-148
  (_start)]`; BL31 provides PSCI for this platform `[doc]` (Trusted Firmware-A documentation,
  Raspberry Pi 4 platform); derivation: the shared step above) `TODO (verify on hardware)`: an
  SMC from EL2 should take an undefined-instruction exception.
- **High peripheral mode has its own stub build.** `armstub8-gic-highperi.bin` uses the full-map
  bases `0x4_C000_0000` and `0x4_C004_1000`; a stub built for one peripheral mode programs the
  wrong addresses in the other. `[inference]` (premises: the `HIGH_PERI` definitions
  `[src:rpi-tools: armstubs/armstub8.S:32-51 (HIGH_PERI)]` and the build rule
  `[src:rpi-tools: armstubs/Makefile:26-27 (CC8)]`; the firmware's own stub lacks high-peripheral
  support `[doc]` (Raspberry Pi documentation, legacy config.txt boot options, `arm_peri_high`))
  `TODO (verify on hardware)`: boot with arm_peri_high=1 and this build.
